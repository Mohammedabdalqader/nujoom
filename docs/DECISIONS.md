## Rebuild (2026-09-28)

**D-002 Final design = the owner's prototype** (commit `9f9017d`, removed from the working tree).

**D-003 Stack: React Native (Expo SDK 57) in TypeScript, not Flutter or fully native.** Reasons:

- The prototype is React plus Tailwind classes. NativeWind 4 (Tailwind 3.4 for React Native) ports it almost one to one.
- The Supabase schema, pure domain logic, i18n and Python worker are TypeScript/SQL/Python and carry over.
- react-native-vision-camera covers segmented recording.

Pinned versions: Expo 57 / React Native 0.86 / React 19.2.3, TypeScript 6.0, Vitest 5, pnpm 12.5, Turborepo 2.11, Node 24.

**D-006 Owner decisions on prototype features (2026-09-28, "go with your recommendations"):**

1. **Stars are reward points.** No JOD value, can't pay for bookings, can't be bought or transferred. The booking sheet shows "cash at the pitch" only. The prototype's "10 stars = 1 JOD" line and stars payment option are removed.
2. **No free-text testimonials.** Endorsements are fixed badges given by match participants.
3. **FIFA attributes come from post-match peer ratings** (1–5 per attribute).
4. **Three named metrics:** Elo for leaderboards; card OVR 1–99 from attributes; form rating x/10 from match scores (spec §6.10).
5. **Friends see online/offline only.** "In a match at <pitch>" is opt-in for adults and never shown for youth.
6. **The derby "predict the winner" callout is removed.**
7. **The tournament-type filter (pro / amateur / family) is hidden** until M12 is approved.
8. **Copy that claims AI cameras or stadium cameras describes phone recording** until M9/M10.
9. **Clip download only for public-eligible clips;** youth follow their guardians' choices.

**D-007 Sign-in: email code or link plus Google** (carried over; the pilot has no SMS provider).

- PKCE on every client; the mobile deep link is `nujoom://auth-callback`.
- Pilot testers use a one-time "tester code" generated by an admin script.
- Custom SMTP (e.g. Resend) is needed before real users: Supabase's default sender only mails project members.

**D-008 Numbers, dates and language** (carried over):

- Arabic uses Western digits (`ar-JO-u-nu-latn`); English uses `en-GB`.
- JOD shows 0–3 decimals. Times always display in Asia/Amman on the 12-hour clock the design uses ("10:00 م", "10:00 pm").
- Mobile always starts in Arabic unless the user chose English. Switching language forces RTL/LTR and reloads.

**D-009 Minimum age 13.** Age groups are computed on the Amman calendar date: U14 is 13, U16 14–15, U18 16–17, ADULT 18 and over. U12 exists in the enum but is disabled.

**D-010 Honest copy.** Prototype sentences that would be false in the pilot are rewritten in the same tone:

- The AI camera becomes phone recording.
- "First aid at every pitch" becomes a real perk.
- "+50 XP" uses the configured value.

Each rewrite is listed in `docs/DESIGN.md` → Copy changes.

**D-011 Database conventions** (carried over):

- Every table has RLS and explicit grants; derived columns are protected by column grants.
- Policy helpers live in the `private` schema.
- Every `SECURITY DEFINER` function pins `search_path = ''`.
- Each migration ends by revoking EXECUTE on private functions from PUBLIC.
- `001-security-baseline.sql` fails on any table without RLS or any unpinned definer function.
- Clients write multi-row business actions only through RPCs.
- Money-like values (XP, stars) are append-only ledgers written by the server.

**D-012 Fail closed on privacy.**

- A profile without a DOB is treated as youth and private.
- Youth visibility is derived from confirmed guardians (the most restrictive wins).
- DOB lives in `profile_private`.
- Guardianship ends only by the guardian or an admin.

**D-013 Admins are rows in `app_admins`,** checked by `private.is_admin()`, not JWT claims. Config and flag edits are audited by trigger.

**D-014 SQL tests without Docker.** `pnpm db:test` runs every migration and pgTAP file on embedded Postgres 18 (`tools/db-test`) with a small stand-in for Supabase's `auth`, `storage` and role objects. CI also runs the real Supabase stack.

**D-015 Mobile styling: NativeWind with semantic tokens, not raw hex.**

- The prototype hard-codes about 70 hex colours. Each maps to a named token (surface, container levels, on-surface, primary, secondary, tints, team colours).
- The tokens are defined twice in `apps/mobile/global.css`, as dark and light CSS variables, so the light theme is a token swap. The prototype used about 300 lines of `!important` overrides instead.
- Where the prototype's light theme left dark-theme colours unreadable on white (secondary emerald text), the light token is darkened. This is the only visual deviation, logged in DESIGN.md.

**D-016 Icons: Material Symbols Outlined, subset into two small fonts** (outlined and filled), rendered by codepoint.

- The prototype uses about 110 symbols, some with the FILL axis.
- React Native can't use variable-font axes or rely on ligatures on Android. So `tools/icons` cuts static FILL=0 and FILL=1 instances and subsets them to the glyphs we use (tens of KB instead of about 10 MB).

**D-017 Fonts:** Rubik (500/700/800/900), Plus Jakarta Sans (400–700) and Space Grotesk (600/700), bundled from `@expo-google-fonts`.

- Rubik contains Arabic.
- Plus Jakarta Sans and Space Grotesk don't, so Arabic in those styles uses the system Arabic font: Noto Sans Arabic on Android, SF Arabic on iOS. That matches how the prototype renders on phones.

**D-018 Sounds are pre-rendered, not synthesized at runtime.**

- `tools/sounds` renders the prototype's five Web Audio patches (same oscillator types, frequencies, ramps and gains) to 44.1 kHz WAV.
- The app plays them with `expo-audio`.
- `navigator.vibrate` patterns map to `expo-haptics`.
- A settings switch mutes sounds (default on).

**D-019 Data layer: TanStack Query plus a typed API module per feature.**

- Screens are thin containers; presentational components take view-model props.
- While R0 has no backend, every query resolves from typed preview data (`src/preview/`). Each feature swaps to Supabase in its milestone without touching the views.
- `EXPO_PUBLIC_PREVIEW=1` keeps preview data for design reviews.

**D-020 NativeWind 5.0.0-rc.0 with Tailwind 4, pinned exactly.**

- NativeWind 4 targets older Expo SDKs. The 5.0.0-rc.0 / react-native-css 3.1.0-rc.0 pair is the one the NativeWind team verified on our exact stack (Expo 57, RN 0.86.3, Reanimated 4.5.1, Worklets 0.10.1).
- Tailwind 4 is also what the prototype was written in, so its `@theme` tokens port directly.
- Settings:
  - `lightningcss` is overridden to 1.30.1 so Tailwind and react-native-css share one build; mixed versions break native compilation.
  - Metro runs with `inlineVariables: false` so the colour tokens stay runtime CSS variables on native. Otherwise the dark values are baked in and the light theme cannot switch.
- Spike results on Android:
  - Compiled natively: gradients (to `experimental_backgroundImage`), glows (`boxShadow`), `animate-ping`/`pulse` (Reanimated CSS animations), `active:scale-*` and opacity modifiers on tokens (runtime `color-mix`).
  - `backdrop-blur` does nothing on native, so the header and tab bar use `expo-blur` on iOS and web.
  - On Android, expo-blur 57 needs a separate capture target around the content, which the navigator's own header and tab bar can't wrap. There the bar is the same translucent surface (`bg-chrome`) without blur.
- Revisit when NativeWind 5 is final.

**D-021 Intl polyfills for Hermes.** Hermes (the JS engine on Android and iOS) has no `Intl.RelativeTimeFormat` or `Intl.PluralRules`.

- The first device run crashed with "undefined cannot be used as a constructor".
- Without PluralRules, i18next would also silently drop Arabic's six plural forms.
- `src/lib/intl-polyfills.ts` loads the formatjs polyfills (getCanonicalLocales, Locale, PluralRules, RelativeTimeFormat) with ar/en data before anything formats text. Each installs only when the engine lacks the API, so browsers keep their built-ins.
- Verified by removing those APIs in the browser: the app renders, "قبل …" relative times and "3 مطلوبين" plurals work. `structuredClone` is avoided for the same reason.

**D-022 Youth leaderboards show "under 18" and "under 16", as the design does.**

- With a minimum age of 13, the U14 group holds only 13-year-olds, too few for a board of its own. So the "تحت 16" (under 16) board covers the U14 and U16 groups, ages 13–15.
- The age groups still exist separately in the data (spec §6.10) for rating and eligibility.
- Adults never appear on youth boards and youth never on the adult board (§7).

**D-023 Friends stay inside an age band and are added by card code.**

- The prototype added anyone by typing a name. A real squad needs the other player's consent, so you send a request with their card code ("NJM-8702") and they accept or decline.
- Lookups and suggestions only return players the viewer may see: public profiles, or city-visible profiles in the same city. Private profiles are never found.
- Friendships never cross the adult/youth line. Presence ("online") is still presence, and §7 gives minors no public presence.
- Card codes are typed on Arabic keyboards too, so the lookup accepts Arabic-Indic digits, lower case, spaces and a missing "NJM-" (`normalizeCardCode`, tested).

**D-024 Clip playback uses `expo-video` (new dependency, 2026-09-28).**

- It is the Expo SDK's own player (SDK 57, config plugin added), works in Expo Go and dev builds, and plays the worker's 720p faststart MP4s from signed URLs.
- `Clip.videoUrl` is null while a clip is still processing; the player then shows the thumbnail and a "still processing" state instead of fake playback.
- `SelectSheet.value` became optional so one-off choices (a report reason) show no preselection.
