# Nujoom production roadmap and truth register

Status: owner-directed working plan, 2026-09-28. Canonical repository: `Desktop/nujoom`. The old `Desktop/Nujoom al-Hara` repository is reference material, not a second implementation target. This document is the shared delivery status and next-work order for Codex and Claude. It is not a claim that planned features exist.

## How this document is used

- `docs/PRODUCT_SPEC.md` defines intended product behavior; `docs/DECISIONS.md` records later approved deviations. This file records **what is implemented, what is verified, what remains, and the order of work**. When these disagree, log the conflict and obtain an owner decision; do not silently mark a plan as shipped.
- `agentic_system/tasks.md` is the execution board, `claims.md` prevents simultaneous edits, and dated `coordination.md` / `handoffs.md` entries carry review evidence. Claude and Codex should update this status at each accepted gate, not from a UI mock or a commit message alone.
- Status vocabulary: **implemented** = code exists; **verified** = named test/evidence passed in the stated environment; **preview only** = demo fixture behavior; **planned** = no working production implementation; **blocked** = cannot complete without an owner, provider, device, or legal dependency.
- No generated person, generated pitch, sample booking, or demo photo is a real player or listed venue. No imported place is bookable just because it has a map pin.
- This is a sequencing plan, not a calendar promise. Estimates require staffing, provider choices, a field-verification budget, and the recording device spike.

## Jordan pitch discovery program (G1)

The owner's [shared discovery discussion](https://chatgpt.com/share/6aba772b-0434-83ed-a920-ee3e8e189799) proposes OSM, Google Places, owner claims and community reports. The owner clarified D-032: first prepare a Nujoom-controlled catalog of available Jordanian pitches and their real field designs; users search **only that prepared catalog**. Both verified and not-verified fields appear, clearly badged. We adopt the multi-source, reviewed-directory objective, with two corrections: this repo is Supabase/TypeScript rather than the discussion's assumed FastAPI service, and Google Places is not a bulk permanent directory source without a separate terms/licensing review.

### Catalog and trust model

1. **Facility versus field.** A facility is a venue/operator/entrance; it may contain multiple physically distinct pitches. An OSM `leisure=sports_centre` feature may describe the facility while `leisure=pitch` features describe fields inside it. Preserve both; never merge two searchable fields because they share a name or GPS point. Record each field's real format/capacity, dimensions or layout where evidenced, surface, indoor/outdoor, lights, amenities and permitted photos. Unknown is a valid value. A football field may be public, school-only, private or closed; `sport=soccer` alone does not prove access or rental.
2. **Separate source from assertion.** Store OSM type/id/version, import timestamp, original geometry/tags and licence lineage in source records. Store owner-provided operational facts separately, with who supplied them, evidence, last confirmation and media rights. Community corrections enter a moderation queue. No third-party image is copied into our asset store without rights.
3. **Independent publication axes.** Track (a) location confidence/review, (b) public accessibility, (c) operator authority and participation, and (d) field-level booking integration. Suggested internal states: candidate -> reviewed searchable listing -> operator contacted/claimed -> authority and field details checked -> live schedule activated. Publication of a prepared listing does not require the operator to have joined. The public badge remains **Not verified by Nujoom** throughout outreach and setup; switch it to **Verified by Nujoom** only when that field is ready for an in-app booking. A claim alone is not verified ownership; one facility may have both badges across its fields. Closed or duplicate records are retained for audit but removed from search.
4. **Public UI contract.** Every searchable field has one clear badge: "Not verified by Nujoom / غير موثق من نجوم الحارة" or "Verified by Nujoom / موثق من نجوم الحارة". Not-verified cards show known design details and location, with unknowns omitted or marked; no fake price, rating, availability, hero photo, Book, match creation or check-in. Only a verified participating field with a live schedule can display slots and Book. A report/correction action is available for bad location, closure, wrong field design or duplicate. Precise directions appear only when coordinate confidence is sufficient; directions are not a reservation.
5. **Suggested schema boundary.** Add `facilities`, physical `pitches`, `source_records`, `discovery_jobs`, `listing_reviews`, `facility_claims`, `outreach_attempts`, `community_submissions`, `verification_events` and media-rights metadata, or equivalent tables after Claude's schema review. Keep a searchable field/listing type with nullable design attributes separate from the current mobile `Pitch` type, which requires price, size and slots. Search queries only the published Nujoom catalog, not an external provider at runtime. PostGIS/spatial indexes are a proposed implementation, not an installed capability until migration/tests prove them.

### What "mostly Jordan" would mean

No current number supports "all" or even "most" pitches in Jordan. A seeded city list and a large pin count are not denominators. Publish a coverage dashboard **per governorate and urban/rural stratum**: candidates, reviewed public listings, location-checked listings, owner-verified venues, bookable fields, duplicate/closed rates, last review age and source mix. Record the date of each import.

Proposed claim gate for the owner's approval: an independently built audit sample in **every governorate**, not sampled from the imported directory, finds at least 80% of in-scope publicly accessible football facilities in the directory, with at least 95% of sampled published pins locating the correct facility and zero unverified listings offering in-app booking. Review a documented sample of rural areas as well as major cities and report confidence/limitations; do not extrapolate an Amman result to Jordan. These 80/95 targets are **proposals, not achieved metrics**. Owner and field team must agree the in-scope definition, sample size, operating budget and the threshold before any national coverage marketing claim.

Freshness is separate from coverage: set a review SLA and visibly mark stale information. A moved, closed or disputed venue is hidden or flagged promptly. Bookable operator inventory needs a much tighter operational SLA than informational OSM locations; Claude and the owner set the exact intervals in the data contract.
